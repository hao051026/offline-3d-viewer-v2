# 小冉学长 · 离线三维建模工作流

大疆司空2 导出的 3DTiles 模型 + 本地矢量标签，**全程不联网**在普通办公电脑上打开、
查看、测量、出图。整套东西在一个文件夹里，拷 U 盘就能带到现场。

> 当前状态：**查看器已可用，真实模型与 36 条标注已接入并验证；整包含 10.54 GB。**

---

## 一、现在就能做的一件事：启动查看器

双击：

```
E:\离线建模工作流\1_模型查看器\启动查看器.bat
```

- 会自动起一个本机服务并打开浏览器（默认 `http://127.0.0.1:8765/index.html`）
- 关闭黑色命令行窗口 = 停止服务

**换一台电脑也能开，不用装 Python。** 启动脚本按这个顺序找路：

| 顺序 | 用什么 | 说明 |
| --- | --- | --- |
| 1 | `py` / `python` | 有 Python 3 就走 `serve.py`（原方案，功能最全） |
| 2 | Windows 内置组件 | 没 Python 就自动用 `serve.ps1`：优先 Windows 自带 http.sys（并发、快），被组策略限制时退回手写的 TCP 服务（慢一点但一定能起） |

两条路的行为完全一致：补 `.b3dm/.glb/.wasm` 的 MIME、源码与 JSON 一律 `no-store`、
提供 `/__model_status` 探测接口、只监听 `127.0.0.1`、不联网。**两种都不需要管理员权限**。

验收数据（同一台机器、同一视角）：真实模型 800 块瓦片的就绪时间
免 Python 版 5 秒（http.sys 通道）/ 8 秒（兜底 TCP 通道），Python 版 4~6 秒，三者基本持平。
无 Python 环境下双击 bat 实测：模型与 36 条标注全部正常显示。

> 免 Python 版启动时会把 `data\model\tileset\` 下约 800 个层级 JSON（8.7 MB）预读进内存。
> 司空2 的瓦片树是一层层串行发现的，不预读的话每个小 JSON 要十来毫秒，首屏会白白等半分钟。
> **换模型之后必须重启服务**，否则页面仍在用旧的层级表。

**不要双击 `index.html`。** `file://` 协议下浏览器会拦掉本地瓦片读取，模型永远加载不出来——这是这类离线三维包最常见的"打不开"原因。

## 二、模型下载完以后：三步接入

| 步骤 | 动作 | 判断成功的标志 |
| --- | --- | --- |
| 1 | 解压司空2 导出的 3DTiles 包，找到 `tileset.json` | 它和一堆 `b3dm`/`glb` 瓦片文件夹在同一层 |
| 2 | 把 `tileset.json` 所在的**整个文件夹**拷进 `1_模型查看器\data\model\tileset\` | 路径是 `data\model\tileset\tileset.json`（不要再套一层同名文件夹） |
| 3 | 什么都不用点，等 5 秒 | 顶栏状态从"等待模型"变"已加载"，相机自动飞到模型范围 |

如果没自动加载，页面点"重新检测"；还不行就跑体检脚本看是文件问题还是层级问题：

```powershell
cd "E:\离线建模工作流\2_数据处理工具"
py -3 检查tileset.py "..\1_模型查看器\data\model\tileset\tileset.json"
```

它会直接告诉你：根包围体中心经纬度、有多少瓦片、**缺了哪几个文件**、总体积多少，
以及有没有 **LOD 断档**（见下一节）。
缺文件 → 重拷；层级错 → 按提示调整。

### 2.1 司空2 这类导出的一个通病：远看整片空白，凑近才出图

**实测结论（本项目真实数据已验证）**：文件是完整的（52687 个文件、10.53 GB、52069 个被引用的 b3dm，缺失 0），
但直接打开会出现"相机在几公里高度看，画面全空、状态栏 `瓦片 0 / N`；
压到单块上方几百米，模型立刻出来"。

原因不在数据，在顶层 `tileset.json` 的写法：每个分块节点是个**纯容器**
（自己不带几何，`content` 挂在它的下一层，指向该分块的子 tileset `.json`），
但它的 `geometricError` 却只写了 3~170 米。Cesium 的细化规则是
"屏幕误差 ≤ 16 就不再往下钻"，于是远距离时它认为"这个容器已经够细了"，
停在那儿——而容器没有几何，画面就是空的。

修法（会先把原始文件备份成 `tileset.json.原始.json`，随时可回滚）：

```powershell
cd "E:\离线建模工作流\2_数据处理工具"
py -3 修复司空2_tileset.py                                    # 修正式模型位
py -3 修复司空2_tileset.py "..\1_模型查看器\data\model\tileset-02\tileset.json"
py -3 修复司空2_tileset.py --revert                          # 回滚
```

它只做两件事：把顶层每个容器节点的 `geometricError` 提到根节点的一半（保证任何
可见距离都会继续下钻到真正带 b3dm 的节点），并给 `root` 补 `refine: REPLACE`。
**不动瓦片文件、不动坐标、不动层级**，10 GB 数据不用重拷。

修完的实测效果：15 km 整体视角 797 块一次就绪、58 万三角面，整条走廊完整可见；
压到 1.5 km 时自动细化到 L18，路面、互通、田块、村庄都清晰。

**司空2 导出的目录长这样，结构别动**

```
tileset.json                      ← 最外层就这一个，接入口
Tile_p000_p002\
    Tile_p000_p002.b3dm           ← 瓦片本体（3D Tiles 标准格式）
    Tile_p000_p002.json           ← 这层的子 tileset，别删，Cesium 靠它往下钻
    Tile_p000_p002_L15_0u.b3dm    ← 更精细一级
    Tile_p000_p002_L16_0uu.b3dm
    ...
Tile_p001_p002\ ...
```

- `.b3dm` 就是司空2 的原生瓦片格式，查看器（CesiumJS）原生支持，**不要转成 glb/obj**，转了会丢 LOD、标签也必然错位。
- 同名 `.json`（子 tileset）**不能删**，也别把 `.b3dm` 从子目录里"压平"搬出来，层级一改就找不到瓦片。
- 文件多是正常的：`L15~L18` 是多级细节，Cesium 按屏幕误差按需加载，不会一次全下。首次打开慢几秒到几十秒，看状态栏"瓦片 已加载"就到位了。
- 拷贝时**整个文件夹一起拷**，保持和导出时一样的层级。

多测段的写法：每个测段一个文件夹（`tileset`、`tileset-02`…），然后在
`1_模型查看器\js\config.js` 的 `models` 里追加一条，顶栏下拉框即可切换。

### 2.2 自己用 Blender 建的模型（.blend）也能进来看

查看器只认 3D Tiles，`.blend` 要先转。工具已备好，**不需要装图形界面 Blender**——
用 `bpy` 这个 Python 模块（本质是 Blender 本体，走 pip 装）就能在命令行里转：

```powershell
# 一次装好（约 750 MB，只在转换这台机器上需要，目标电脑不用装）
uv pip install --python .venv_bpy\Scripts\python.exe `
    --index-url https://pypi.tuna.tsinghua.edu.cn/simple bpy

# 只看模型结构，不导出（物体数/三角面/真实包围盒）
.venv_bpy\Scripts\python.exe "2_数据处理工具\blend转3dtiles.py" "..\data\model\小镇（blend）\小镇.blend" --no-export

# 正式转换：输出 GLB + tileset.json 到 .blend 旁边
.venv_bpy\Scripts\python.exe "2_数据处理工具\blend转3dtiles.py" `
    "..\data\model\小镇（blend）\小镇.blend" --lon 108.9 --lat 34.0 --height 500
```

转换器会自动做三件容易踩坑的事：

1. **按真实包围盒算 tileset**——`boundingVolume.box` 用实测半轴，`transform` 用 ENU 矩阵，
   并让模型**底面**落在 `--height` 上，而不是中心落地（否则一半埋进地里）。
2. **排掉装饰物体**——Blender 场景里的天空背景板、云片、雾板（`clouds*`/`mist*`/`fog*`
   以及 ≤2 面且面积巨大的贴图板）在 GIS 里只会挡住视线，默认删掉。想保留加 `--keep-plates`。
3. **中文路径**——全程按 UTF-8 处理，目录名带中文/全角括号也能跑。

实测（本项目三个模型）：

| 模型 | 源格式 | 原始 | 转换结果 |
| --- | --- | --- | --- |
| 小镇（blend） | `.blend` | 153 物体 / 257,717 面 | 147 物体 / 257,705 面 → 78.1 MB GLB |
| 教室 | `.blend` | 154 物体 / 149,201 面 | 153 物体 / 147,465 面 → 6.9 MB GLB |

> `.max`（3ds Max）**不能转**：它是 OLE2 容器 + Max 私有序列化，没有可用的开源解析器。
> 要么在 3ds Max 里 `导出 > glTF/OBJ/FBX`，要么让 Blender 用 FBX 中转。

## 三、把司空2 的病害标注叠到模型上

司空2 里画好的病害点/线/面，导出 KML 后转成查看器的标签 JSON——**坐标不用换算**，
因为司空2 导出的模型和标注用的是同一套 WGS84 经纬度。

```powershell
cd "E:\离线建模工作流\2_数据处理工具"
py -3 kml转标签json.py "D:\司空2导出\defect.kml" -o "..\1_模型查看器\data\vector\labels.json" --name "小冉学长病害"
```

跑完把输出的 `labels.json` 放进 `1_模型查看器\data\vector\`，刷新页面即可。
脚本会把 KML 描述里的 `病害等级: B`、`长度: 0.42m` 这类内容自动拆成属性表，
点标签就能看到；值如果是图片路径会自动出缩略图。

想直接用 KML 也行：把 `defect.kml` 放到 `data\vector\`，在 `config.js` 里把
`dj-kml` 那一行的 `enabled` 改成 `true`。查看器会自动把 KML 里指向外网的图标
换成本地图标（否则离线环境下图标会裂）。

标签 JSON 的字段说明写在 `data\vector\labels.json` 开头的 `_字段说明` 里，手工加几条也不难。

### 3.1 真实案例：重点拥堵路段.kml（36 条标注拆成 4 组）

一份司空2 导出的 KML 往往混着点、长线、一堆同名的短线段（比如"应急车道放行"被
切成了 23 段）。全塞进一个分组会糊成一片，所以脚本支持按类型/名称/地理范围拆组，
同一条 KML 跑几遍、`--append` 追加到同一个 JSON 就行：

```powershell
cd "E:\离线建模工作流\2_数据处理工具"
$kml = "..\1_模型查看器\data\vector\重点拥堵路段.kml"
$out = "..\1_模型查看器\data\vector\拥堵路段.json"

# 1) 模型范围内的设施点（LED 屏、指示灯、红绿灯）
py -3 kml转标签json.py $kml -o $out --name "路段设施·模型内" --group-id facility --color "#e23c39" --only-type point --clip "120.000000,30.000000,5000"

# 2) 模型范围内的应急车道线（23 段放行 + 上下行两条长线），线不打文字标签
py -3 kml转标签json.py $kml -o $out --append --name "应急车道·模型内" --group-id lane --color "#ffb020" --only-type polyline --exclude-re "建模范围" --no-line-labels --clip "120.000000,30.000000,5000"

# 3) 落在模型范围之外的那批，单独成组并默认隐藏
py -3 kml转标签json.py $kml -o $out --append --name "模型范围外（无法叠加）" --group-id outside --color "#7a869a" --exclude-re "建模范围" --no-line-labels --clip "120.000000,30.000000,5000" --clip-mode outside --hidden

# 4) "建模范围"那条描线（在模型以北 15 km，默认隐藏）
py -3 kml转标签json.py $kml -o $out --append --name "建模范围（原始描线）" --group-id scope --color "#2d8cf0" --name-re "建模范围" --no-line-labels --hidden
```

新增参数：

| 参数 | 作用 |
| --- | --- |
| `--only-type point/polyline/polygon` | 只收某一类几何，点、线分家 |
| `--name-re` / `--exclude-re` | 按名称正则收 / 排（同名短线归一组，描线单独拎出来） |
| `--no-line-labels` | 线/面不打文字标签（23 条同名短线不糊屏，点要素照常有文字） |
| `--clip lon,lat,半径米` + `--clip-mode inside/outside` | 按模型包围球切分"模型内 / 模型外" |
| `--hidden` | 该分组默认隐藏，图层面板里还能再打开 |

这一份的实测结果（`data\vector\拥堵路段.json`，36 条全部转出）：

| 分组 | 条数 | 颜色 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| 路段设施·模型内 | 5 | 红 `#e23c39` | 显示 | 单悬臂 LED 屏/指示牌、红绿灯，落位在路面和路侧 |
| 应急车道·模型内 | 20 | 橙 `#ffb020` | 显示 | 23 段放行里的 20 段 + 上下行两条长线，线沿车道铺开 |
| 模型范围外（无法叠加） | 10 | 灰 `#7a869a` | 隐藏 | 5 个点 + 5 条线在模型以北 10.3~12.8 km |
| 建模范围（原始描线） | 1 | 蓝 `#2d8cf0` | 隐藏 | 5 个点的小描线，在模型以北 15.7 km |

**要注意的一条**：这份 KML 里有 11 条标注落在模型覆盖范围之外（北侧 北段那批
和"建模范围"描线），模型只覆盖到 更北的区域，所以它们会飘在纯色背景里。
这是**数据范围对不上**，不是标签错位——已单独成组并默认关掉，图层面板里能随时打开核对。
司空2 里看到的"建模范围"和实际下载的瓦片范围也可能不是同一块，接入前最好核对一次。

## 五、必须知道的一个坑：高程基准

司空2 导出的高程是 **WGS84 椭球高（HAE）**，不是我们台账上用的 **海拔（ASL）**。
在这一带两者差 **30~50 m**。

- 只加载模型看形状：不受影响，不用管
- 把实测海拔的病害点标上去：标签会整体飘在模型上方约 40 m
- 修法：用"校正"面板把高程往下压到贴合，或者统一在转换前把标签高程改成椭球高

**实测结论（本项目这份）**：司空2 自己画的标注导成 KML 后，高程和模型路面是同一基准，
不用补。在 某个点位做过对比——标签高程 510.8 m，模型面上拾取到 509.6 m，
差 1.2 m，肉眼看就是贴在路面上。所以需要修正的是**台账/外业实测的海拔**，不是司空2 的标注。

线要素另有一个小坑：司空2 的线高程常比路面低一两米，直接画会被路面的深度测试吃掉（看不见）。
查看器现在对线统一关了深度测试、并抬高 `label.lineLiftM`（默认 0.5 m），线一定浮在路面之上可见，
代价是线会略微"透"过一切物体显示——查线要素时这是想要的，看遮挡关系时把该分组关掉即可。

这不是模型错了，是两套高程基准没对齐。搞不清差多少时，先在模型上点一个已知点位，
用属性面板读回的椭球高和台账海拔一比，差值就是你的修正量。

## 七、边界（先把预期说清）

- **只读查看**：能看、能量、能出图、能显隐，**不能**在这个界面里新增病害再回写司空2。
  外业要新增标注，仍在司空2/移动端做，回来导 KML 重跑一次转换脚本即可。
- **不联网**：不请求任何在线影像、地形、ion 服务、geocoder。代价是**没有影像底图**，
  三维模型之外是纯色背景——这是刻意的，离线现场网络不可靠。
- **不转坐标系**：全部用 WGS84 经纬度 + 椭球高。转局部 ENU 会同时毁掉模型 LOD 和标签对齐。
- 免 Python 启动已经做了（`serve.ps1`，Windows 10/11 自带组件即可）。
  再要一个"双击一个 exe、不弹黑色命令行窗口"的版本，那是打包的事（Electron 或 PyInstaller），
  界面和逻辑不用改，属于可选增强，不是必需品。

## 八、拷到 U 盘 / 换电脑

**要拷的是整个 `离线建模工作流` 文件夹**，不要只拷 `1_模型查看器` 里的某几层：

```
离线建模工作流\            10.54 GB / 52867 个文件
├─ 1_模型查看器\               ← 唯一必需（含 10.5 GB 模型）
├─ 2_数据处理工具\             ← 下次转标注要用，建议一起带
└─ 3_成果输出\                 截图报告，可带可不带
```

| 事项 | 要求 |
| --- | --- |
| U 盘容量 | ≥ 12 GB |
| U 盘格式 | exFAT 或 NTFS 最稳；FAT32 也能用（最大瓦片只有 55 KB，不会碰到 4 GB 单文件上限），只是小文件多、拷贝慢 |
| 拷贝时间 | USB 3.0 约 10~20 分钟（5 万多个小文件，瓶颈在文件数不在体积） |
| 目标电脑 | Windows 10/11 + 一个现代浏览器（Chrome / Edge / 火狐）。**不需要装 Python**；显卡要能跑 WebGL（十年前的集显可能打不开三维） |
| 目标电脑装什么 | 什么都不用装：双击 `启动查看器.bat` 即可 |

包里必须保留、别整理掉的几样：

- `data\model\tileset\` 整目录（`tileset.json` + 798 个 `Tile_pXXX_pYYY\`），**不要压平、不要拆**；
- 同目录的 `tileset.json.原始.json`（修补前的备份，将来想回滚用，`修复司空2_tileset.py --revert`）；
- `data\vector\`（`拥堵路段.json`、原始 KML、标签图标）；
- `lib\cesium\`（本地 Cesium，删了就没有三维引擎了）。

到新机器上不值得做的三件事：不要重新导出模型、不要把 `.b3dm` 转格式、不要改 `tileset.json`
里的层级——那三件都会把已经修好的 LOD 和标签对齐重新弄坏。

# 离线三维模型查看器 · 现场使用说明

## 启动

双击 `启动查看器.bat`。浏览器会自动打开，地址 `http://127.0.0.1:8765`（端口被占会自动换）。

- **没装 Python 的电脑也能双击**：脚本先找 `py` / `python`，找到就走 `serve.py`；
  找不到就自动改用 Windows 自带组件（`serve.ps1`），效果一样，只是启动方式不同。
  命令行窗口第二行会写明走的是哪条路。
- **不要双击 `index.html`**：`file://` 下浏览器禁止读本地瓦片，模型一定加载不出来。
- 黑色命令行窗口就是服务本体，关掉它 = 关闭查看器。
- 全部离线：不请求在线影像/地形/ion，飞机上没有网也能用。
- 正式模型还没放进来时，点引导页的 **「先看自检模型」**（或顶栏下拉切到"自检模型（演示）"）
  可以先验软件：能转、能点标签出属性，就说明查看器正常，问题只会在模型文件那头。
- **换电脑 / U 盘**：整个文件夹拷走即可，不需要在目标机装任何东西；
  U 盘用 exFAT/NTFS，留 12 GB 以上。
- **换了模型要重启服务**：启动时会把 `data\model\tileset\` 下的层级 JSON（约 800 个）
  预读进内存，好让 800 块瓦片 5 秒内出图；替换模型后必须关掉黑窗口再双击一次，
  否则页面还在用旧的那份层级表。

## 界面

```
顶栏    测段下拉 · 模型状态 · 全屏
左侧    图层 / 属性 / 测量 / 校正 / 截图
中间    三维视图
右栏    选中项详情（点标签或模型面才出内容）
底栏    瓦片数 · FPS · 当前经纬度与视高 · 操作提示
```

## 快捷键

| 键 | 作用 |
| --- | --- |
| `1` | 回到模型全景（按当前飞行俯仰角） |
| `2` | 正俯视（看平面、定桩号位置） |
| `3` | 低角度斜视（查墩身、桥底、边坡） |
| `Esc` | 结束测量 / 收起右侧面板 |

## 模型加载不出来时

按顺序排，八成第一步就能解决：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面只有引导页，状态"等待模型" | `data\model\tileset\tileset.json` 不存在 | 把司空2 导出的整包拷进来，`tileset.json` 必须在最外层 |
| 分不清是软件坏了还是模型坏了 | 不确定 | 点「先看自检模型」；立方体能出来 = 软件没问题，故障在模型文件 |
| 状态"加载失败"，提示 tileset 读取失败 | 层级套深了一层 / 用了别的服务 | 用 `检查tileset.py` 定位；启动一律用 `启动查看器.bat` |
| 模型加载一会儿停住、缺一块 | 瓦片没拷全 | `py -3 检查tileset.py <路径>` 会列出缺失文件，整包重拷 |
| 整页白屏、控制台报 MIME / wasm | 静态服务没补 `.b3dm`/`.wasm` 的 MIME | 必须用本目录的启动方式（`serve.py` 或 `serve.ps1`，都已补 MIME），别用 IIS/其他静态服务 |
| 浏览器打不开 127.0.0.1 | 端口被占或防火墙 | 命令行会打印实际端口，照着改地址；或 `--port` 指定 |
| 画面全黑、状态栏瓦片一直停在 `0 / N` | 浏览器窗口被最小化/切到后台，三维渲染被系统暂停了（省电） | 把窗口还原到前台，一两秒内瓦片就会开始加载；这是浏览器行为，不是查看器故障 |
| **远看整片空白**、瓦片停在 `0 / N`，压到几百米高才出图 | 司空2 导出的顶层 `tileset.json` 里，分块容器节点的几何误差写得太小，Cesium 远距离时不再往下钻，而容器本身没有几何 | 跑一次 `py -3 修复司空2_tileset.py`（会先备份 `tileset.json.原始.json`），刷页面即可；详见 README 2.1 |
| 首屏相机飞到很远的太空、模型只剩一条细线 | 加载瞬间 tileset 包围球还没就绪，自动摆位算错 | 已加兜底（加载后 0.5 s / 1.6 s 各校验一次）；若仍遇到，点一次「重新加载」 |
| 双击 bat 后黑窗口一闪就没了 / 提示"服务已退出" | 8765~8824 全被占，或这台电脑的组策略禁止运行 PowerShell 脚本 | 先关掉其他查看器窗口；仍不行就在命令行里看报错。组策略限制时用 Python 版，或让 IT 放开 `-ExecutionPolicy Bypass` |
| 提示"没有找到 Python"但仍能打开 | 正常现象 | 说明走了 Windows 内置组件那条路；窗口第二行会写 `运行方式 : Windows 内置组件 HttpListener` |
| 启动日志里出现 `Python 退出码 = 9009` | 这台电脑的 `python` 是微软商店的假壳（`...\WindowsApps\python.exe`），`where` 能查到但执行必失败 | 启动器已自动跳过它并改用 Windows 内置组件；日志里会紧跟一行「Python 启动失败，自动改用 Windows 内置组件」 |

## 标签对不上时

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 标签整体悬在模型上方几十米 | 高程用了海拔（ASL），模型是椭球高（HAE） | "校正"面板把高程往下压，差值在模型上点已知点位读出来 |
| 个别测段整体偏一边 | 导出时该段基准不一致 | "校正"面板东/北向微调，点"记住这组值"下次自动套用 |
| 标签贴着模型表面闪烁 | 深度冲突 | 已默认关闭深度测试；若仍闪烁，把标签 `showLabel` 设 false 只留图标 |
| **线要素看不见 / 只看到断断续续几条** | 司空2 的线高程常比路面低一两米，被路面深度测试吃掉 | 已默认对线关闭深度测试并抬高 `label.lineLiftM`（0.5 m）；若仍不理想，把该值调到 2~3 |
| **一批标注飘在模型外的纯色背景里** | 那几条标注本来就在模型覆盖范围之外（司空2 里画的范围和实际下载的瓦片不是同一块） | 图层面板里"模型范围外（无法叠加）"这一组默认是关的，打开可核对；要正式用，得重新下载覆盖那一段的瓦片 |
| 图标是白色小方块 | KML 引用了外网图标 | 查看器已自动替换成本地图标；改用 JSON 标签层更彻底 |
| 上千个标签后变卡 | 文字标签过多 | `config.js` 里调小 `label.hideTextDistance`（远处只留图标），或分组显隐 |

## 换一批标注（司空2 新导出的 KML）

1. KML 先放到 `data\vector\`（原始件留一份，别只留在桌面）
2. 在 `2_数据处理工具` 里跑 `kml转标签json.py`，一条命令转成一组：
   `py -3 kml转标签json.py <kml> -o "..\1_模型查看器\data\vector\xxx.json" --name "分组名" --color "#e23c39"`
   点、线要分开看就加 `--only-type point` / `--only-type polyline --no-line-labels`，多次运行加 `--append` 累到同一个 JSON
3. `config.js` 的 `labels` 里加一行（或用已有的那行改 `url`），`enabled: true`
4. 刷新页面；分组名、颜色、默认显隐都写在 JSON 的 `groups` 里，不用改代码

```js
{ id: "congestion", name: "拥堵路段标注", type: "json", url: "data/vector/拥堵路段.json", enabled: true, color: "#ffb020" }
```

## 调性能（`js\config.js`）

- `scene.maxScreenSpaceError`：`16` 默认。卡就调到 `24`，还卡就 `32`；要更清晰调到 `8`
- `label.hideTextDistance`：默认 `1500` 米，超过就不显示文字
- 标签按分组显隐，比一次性显示全部流畅得多
